## What this project is

DeepSeek Harness (`dsh`) is an open-source agent harness from DeepSeek. The repository description uses the slogan "Everything is a Plugin." Cordis, vendored under `vendor/`, is the plugin framework: plugins contribute services, typed events, and reversible effects to a shared context. The ordered map of composition, the loop, and extension points is [architecture.md](architecture.md). The Cordis ideas a plugin author needs are the [primer](cordis-primer.md).

### Runtime

A running `dsh` is a plugin tree composed at boot. The product launcher is [`apps/cli`](../apps/cli/README.md). `pnpm dsh` runs `node --import tsx/esm apps/cli/src/bin.ts`. `dsh web` is the alias of `--profile web` and, as the root README states, serves the Web UI at `http://127.0.0.1:3080` by default. `dsh --profile headless "..."` runs one persisted session and exits. A production run from a checkout uses artifacts from `pnpm run build`. The source launcher does not rebuild those artifacts.

A **profile** is a named composition under the Harness home (`$DSH_HOME`, default `~/.dsh`). It lists composition bundles, can install out-of-tree plugins, and keeps `cordis.patch.yml`. `web` and `headless` ship as templates. A **composition bundle** distributes Cordis config rows and the code they mount. [`dsh-base`](../packages/bundle/base/README.md) is the first layer of every profile. [`dsh-web-app`](../packages/bundle/web-app/README.md) adds the browser application. [`dsh-headless`](../packages/bundle/headless/README.md) adds the one-shot runner. Layers apply over an empty entry list: each bundle in profile order, then the profile patch, then `$DSH_HOME/cordis.patch.yml`, then any `--patch` overlay. `dsh --profile web --dump-config` prints the composed tree.

### Plugin model

Product behavior is added by mounting another plugin. A registration goes through `ctx.effect()` or `ctx.on()`, and the registry's `register()` returns the disposer that runs when the plugin unloads. A **seam** is one swappable capability with three roles: Service Definition, Service Provider, and Consumer. Reserve the word for that complete capability. The glossary entry is [capability-seam](glossary.md#capability-seam). An extension point is a separate concept: an event or registration site where a plugin observes or intercepts work. Session events are durable log facts. Agent events (`agent/*`) carry a live agent. Capability events attach policy and adapters.

Anything that reaches a model request must be reconstructable from the session log, so a new model-visible input needs a session event. At this snapshot `SESSION_FORMAT_VERSION` in `packages/core/session/src/types.ts` is `0`, and SQLite persistence uses `SCHEMA_VERSION` `17` in `packages/session/session-persistence-sqlite/src/schema.ts`. A build that does not know a required session-event type refuses the log unless that event is marked ignorable. Only a structural format change bumps `SESSION_FORMAT_VERSION`.

## Understand this before editing

Read [architecture.md](architecture.md) before changing `packages/`. Read [development.md](development.md) before the first install. Standing orders for agents are [AGENTS.md](../AGENTS.md).

### Concepts

- A plugin is the unit of product behavior. Function plugins named-export `name`, `inject`, `Config`, and `apply`, and have no default export. Service packages default-export their service class. Mixing the forms makes the Loader drop the function plugin's namespace. The incident record is [postmortem 0001](postmortem/0001-acp-default-export-drops-inject.md).
- `inject` names required services. The plugin waits until those services exist, so boot order is a dependency declaration.
- Other plugins find a service by a context key such as `ctx.tools`, `ctx.llm`, or `ctx.sessions`.
- Events use declaration merging. Dispatch is `emit`, `waterfall`, `parallel`, or `serial`. A waterfall listener receives `next` and must call `next()` to delegate. Returning without `next()` short-circuits the chain.
- A turn drains admitted input. A step is one model request plus the tools that request calls. The sequence is drawn in [architecture.md](architecture.md).
- Host and Client are two TypeScript programs. One program must not include both `Context` merges. A new package registers in exactly one aggregate. The layout rules are in [development.md](development.md).

### Extension points

The mechanism table in [architecture.md](architecture.md) is the authority for where a change goes. The usual choices are:

- A model provider registers an adapter on `ctx.llm`. Follow [adding an LLM adapter](cookbook/adding-an-llm-adapter.md).
- A model-facing tool registers on `ctx.tools`. Follow [adding a tool](cookbook/adding-a-tool.md).
- A human slash command registers on `ctx.commands` and does not start a model turn.
- Filesystem, shell, subprocess, sandbox, and web capabilities each have their own service key. Add a provider when that seam already exists.
- Durable state extends `SessionEventMap` and is rendered from the log.
- Per-session composition uses a preset `cordis.yml` through [`packages/preset`](../packages/preset/README.md).
- Out-of-tree plugins install into a profile with `dsh plugin` and then show up in that profile's patch layer.

Package creation steps are in [adding a package](cookbook/adding-a-package.md). Tool, hook, and UI plugin shapes are in the [extension cookbook](cookbook/extension-cookbook.md).

### Configuration, credentials, and providers

`cordis.yml` accepts `!!js` under a plugin's `config` and under an entry's `disabled` field. Other entry metadata stays literal. When `!!js` cannot express the condition, composition uses an overlay. Loader rules are in the [primer](cordis-primer.md).

Configuration stores credential references, not secret values. [`dsh-credentials-local`](../packages/credentials/credentials-local/README.md) resolves four layers: the launching environment, then `$DSH_HOME/.credentials.yaml`, then `<cwd>/.env`, then `$DSH_HOME/.env`. The launching environment wins. The product CLI reads a frozen environment snapshot, so a variable exported after startup stays invisible until the next start.

[`dsh-llm-deepseek`](../packages/llm/llm-deepseek/README.md) owns the provider route `deepseek-official`. Its `apiKeyEnv` defaults to `DEEPSEEK_API_KEY` and is resolved on each request through `ctx.credentials`. An omitted `baseURL` uses `DEEPSEEK_BASE_URL`, then the public API. [`dsh-llm-pi-ai`](../packages/llm/llm-pi-ai/README.md) is one plugin whose config is a dict of provider profiles. Each profile's `apiKeyEnv` is a reference such as `OPENAI_API_KEY`. Registering the same route twice throws. The family map is [packages/llm](../packages/llm/README.md).

### Plugin lifecycle

The Loader mounts an entry after the injections that entry declares are active. `apply`, or the service constructor, registers effects. When that plugin's fiber unloads, or the config row is removed, those disposers run. A contribution that remains after unload is a defect, and the package tests have to show the removal. Hot reload is the vendored HMR plugin described in [vendor/README.md](../vendor/README.md). A self-contained misconfiguration fails at load. Any other misconfiguration fails at the first moment it can be detected. A missing referent is reported, not skipped.

## Preparation checklist

The steps below are the setup procedure. The contributor reference behind them is [development.md](development.md).

### Toolchain

- Node.js must satisfy `engines.node` in the root `package.json`: `^22.19.0 || >=24.0.0`. CI's primary version is Node 24, from `PRIMARY_NODE_VERSION` in `.github/workflows/ci.yml`. Further CI lanes run Node 22.19 and Node 26.
- The package manager is Corepack-enabled pnpm. The root `packageManager` field is `pnpm@11.7.0`.
- Bun is not named by `packageManager`, `engines`, or the CI workflow. Install and task scripts in this repository are pnpm scripts.
- Git must be 2.26 or newer. `pnpm install` runs `scripts/install-lefthook.mjs`, which installs worktree-local Lefthook hooks and the translation-pairing merge driver.
- `pnpm install` needs network access to the npm registry. On the analysis machine the default `node` binary was v22.14.0, below the engine floor. Node v22.22.2 from nvm satisfies the range.

### Environment

Put secrets in a gitignored `.env` at the repository root, or export them in the shell. Do not commit key material.

| Variable | Role at this snapshot |
|---|---|
| `DEEPSEEK_API_KEY` | Authorizes live DeepSeek calls, the headless and ACP demos, and real-API e2e. Those e2e tests skip themselves when the variable is unset. |
| `DEEPSEEK_BASE_URL` | Optional API base for the direct DeepSeek adapter when plugin `baseURL` is omitted. |
| `DSH_HOME` | Harness home. When unset, the home is `~/.dsh`. Profiles, `.credentials.yaml`, and `.anonymous-user-id` are stored there. |
| `DSH_PERMISSION_MODE` | Sandbox mode for the base bundle. When unset, the mode is `workspace-write`. `danger-full-access` also selects approval policy `never`. |
| `DSH_TELEMETRY_MODE` | Consent for session-log export. Unset and empty both resolve to `DISABLED`. `FULL` and `FEEDBACK_ONLY` opt in. |
| `DSH_TELEMETRY_DISABLED` | Any non-empty value, including `0` and `false`, disables the telemetry row before load. |
| `DSH_TELEMETRY_OTLP_URL` | Optional OTLP/HTTP logs endpoint used when export is enabled. |

`DSH_TELEMETRY_DISABLED` stops telemetry export. An authorized DeepSeek request can still create the anonymous user id. That split is recorded in the [anonymous user id Agent Note](../.agents/notes/implemented/feature/2026-07-31-telemetry-anonymous-user-id.md).

### First run

From the repository root:

```sh
corepack enable
pnpm install
pnpm run typecheck
pnpm run build
pnpm dsh web
```

`pnpm run typecheck` is the setup completion check in the development guide. Run `pnpm run build` before `pnpm dsh web`, `pnpm dsh --profile headless "task"`, `pnpm run demo:cordis`, and `pnpm run demo:acp`. The headless, Cordis, and ACP demos need `DEEPSEEK_API_KEY`. `pnpm run test` is the keyless Vitest run. `pnpm run test:e2e` is the real-API suite and skips itself when the key is absent. `pnpm run test:snapshot` replays keyless ACP and headless transcripts.

### Checks and reading

Choose the check that covers the edit. Documentation edits run `pnpm run doc-sync`. Behavior edits run the owning Vitest file. Product output that a user or a model can see updates a keyless snapshot under `examples/`. Selection rules are in [AGENTS.md](../AGENTS.md) and [testing.md](testing.md). CI owns coverage, the Node matrix, and built-artifact smokes. Leave `pnpm run test:coverage` for a repository-wide change or for diagnosis of a coverage failure.

Every document under `docs/` is an English and Chinese pair: `foo.md`, `foo.zh.md`, and `foo.i18n.yaml`. An edit to either side updates the other side and then runs `pnpm run verify-translation-pairing --write <pair>`. The contract is [i18n/README.md](i18n/README.md).

## Recommended path for this fork

The plan in this section follows the 2026-09-28 snapshot. It is a working plan for this fork, not an upstream product decision.

### Extend by plugin

Put behavior that should survive an upstream sync into a plugin. Mount it from a profile `cordis.patch.yml`, from an out-of-tree package installed with `dsh plugin`, or from a new workspace package that follows [adding a package](cookbook/adding-a-package.md). When a seam already exists, add a Service Provider for it and keep the existing Consumer. When the model must see the new behavior, add the session event in the same change. A change to `packages/core/agent-loop` also updates [architecture.md](architecture.md) in that change.

Fork core in-tree only when the extension points cannot express the behavior. Keep that work on a branch whose unique commits stay small enough to rebase onto parent `master`.

### Keep master able to fast-forward

On 2026-09-28, fork `master` was an ancestor of parent `master`. While that remains true, the following sequence updates the fork with a fast-forward:

```sh
git remote add upstream https://github.com/deepseek-ai/deepseek-harness.git
git fetch upstream
git checkout master
git merge --ff-only upstream/master
git push origin master
```

Add the `upstream` remote once. After this fork contains a commit that parent `master` lacks, `--ff-only` fails and the update is a merge or a rebase. Keep GitHub `master` as that fast-forward mirror, and land secondary-development commits on other branches. A fast-forward across these 7030 commits moves `package.json` off `0.1.1-rc.2` and can raise `SCHEMA_VERSION`. Session databases written by this snapshot can then fail to open. Copy `$DSH_HOME` before the first boot of the updated tree.

### Branches and pull requests

This fork contains the upstream template [.github/pull_request_template.md](../.github/pull_request_template.md). The upstream review convention in [AGENTS.md](../AGENTS.md) asks for one `kind/*` label, the material `area/*` labels, and an Agent Note when a change alters behavior, architecture, a shared contract, process, testing strategy, or an on-disk format. The tree that was read does not add a fork-specific label set or issue tracker. Use that template until the fork documents a replacement.

Keep a documentation-only change or a plugin-only change on a branch other than `master`, and keep an upstream sync in its own pull request. A sync mixed into a feature branch makes the fast-forward or rebase harder to review.

### Areas that break sync

- Edits under `vendor/*/src` must be logged in [vendor/README.md](../vendor/README.md) and re-applied on every Cordis sync.
- `SessionEventMap`, `SESSION_FORMAT_VERSION`, and SQLite `SCHEMA_VERSION` are compatibility boundaries. This snapshot's pre-release stance rejects old on-disk formats.
- Generated catalogs, including `docs/tool-catalog.md`, `docs/config-catalog.md`, `docs/module-graph.md`, and the Cordis API pages, are regenerated from source. Change the generator input.
- One TypeScript program that includes both Host and Client `Context` merges fails the build. Follow [development.md](development.md).
- Prompt text, tool schemas, and other model-visible strings are behavior. Cover them with the snapshot or e2e tier in [testing.md](testing.md).
- `pnpm run doc-sync` fails when a bilingual pair is missing one side, or when a non-trivial product change has no Agent Note.

## Pitfalls and open questions

- The root README still gives the upstream clone URL. A teammate who follows that URL does not clone this fork.
- `pnpm dsh` before `pnpm run build` starts the source launcher, and a production run still requires the built package and frontend artifacts. The development guide states that requirement.
- Files under `$DSH_HOME` are readable by tool processes that run as the same user. The credentials-local README states that mode `0600` does not hide `.credentials.yaml` from the agent.
- The default telemetry mode is `DISABLED`. `DSH_TELEMETRY_MODE=FULL` or `FEEDBACK_ONLY` exports session-log material. A non-empty `DSH_TELEMETRY_DISABLED` keeps the run local even when the mode is changed.
- Node older than 22.19 is outside `engines.node`. The analysis environment showed this: its default `node` was v22.14.0.
- The ahead and behind counts are a 2026-09-28 observation. Refresh them before planning a sync.
- Open question: the Origin repository `eqkk/deepseek-harness` was not readable from this environment. Confirm whether it mirrors `eqkkk/deepseek-harness` or contains other commits.
- Open question: whether the first product patch should fast-forward to upstream `master` or stop at tag `dsh-v0.1.7-rc.2`. Both are fast-forwards from this HEAD. `master` was 155 commits after that tag.
- Open question: which profile is the product target (`web`, `headless`, ACP, JSON-RPC, or the Python SDK). The first plugin should be proven in that profile's `cordis.yml`, because the extension point differs.
- Open question: which model routes besides `deepseek-official` must work on the first day. Routes that pi-ai already knows are configuration on `dsh-llm-pi-ai`. A protocol the seam cannot express needs a new adapter package.
