# 二开准备指南

[English](二开准备指南.md) | 中文

本参考是 GitHub fork [eqkkk/deepseek-harness](https://github.com/eqkkk/deepseek-harness) 上二次开发（二开）的阅读地图。它记录 2026-09-28 核对过的仓库事实，并链接架构、环境搭建和扩展工作各自的所属文档。本页有意不进入 [website/docs.ts](../website/docs.ts)，因此文档网站不发布这份快照。把文中的计数当作当前值之前，先按 [Fork 快照](#fork-snapshot) 的方法刷新。

## 这个项目是什么

DeepSeek Harness（`dsh`）是 DeepSeek 的开源 agent harness（智能体框架）。仓库描述使用口号 “Everything is a Plugin.”。Cordis 以源码形式放在 `vendor/`，它是插件框架：插件向共享 context 贡献服务、带类型的事件，以及可撤销的 effect。组装、循环和扩展点的有序地图是 [architecture.md](architecture.zh.md)。插件作者需要的 Cordis 概念见[入门](cordis-primer.zh.md)。

### 运行时

一次运行中的 `dsh` 是启动时组装出来的插件树。产品启动器是 [`apps/cli`](../apps/cli/README.zh.md)。`pnpm dsh` 执行 `node --import tsx/esm apps/cli/src/bin.ts`。`dsh web` 是 `--profile web` 的别名；根 README 写明，它默认在 `http://127.0.0.1:3080` 提供 Web UI。`dsh --profile headless "..."` 运行一个已持久化的会话然后退出。从检出目录做生产运行时，使用 `pnpm run build` 产出的产物。源码启动器不会重新构建这些产物。

**profile** 是存放在 Harness home（`$DSH_HOME`，默认 `~/.dsh`）中的具名组装。它列出组合包，可以安装树外插件，并保存 `cordis.patch.yml`。`web` 和 `headless` 作为模板随发行版交付。**组合包**分发 Cordis 配置项以及这些配置项所挂载的代码。[`dsh-base`](../packages/bundle/base/README.zh.md) 是每个 profile 的第一层。[`dsh-web-app`](../packages/bundle/web-app/README.zh.md) 增加浏览器应用。[`dsh-headless`](../packages/bundle/headless/README.zh.md) 增加一次性运行器。各层施加在一份空的条目列表之上：先按 profile 的顺序施加每个组合包，然后是 profile 的 patch，然后是 `$DSH_HOME/cordis.patch.yml`，最后是任意 `--patch` overlay。`dsh --profile web --dump-config` 打印组装后的树。

### 插件模型

产品行为通过再挂载一个插件来增加。注册走 `ctx.effect()` 或 `ctx.on()`，registry 的 `register()` 返回插件卸载时执行的 disposer。**seam** 是一个可替换能力，包含三种角色：Service Definition、Service Provider 和 Consumer。这个词只用于该完整能力。术语条目是 [capability-seam](glossary.zh.md#capability-seam)。扩展点是另一个概念：插件在其上观察或拦截工作的事件或注册位置。会话事件是持久日志事实。Agent 事件（`agent/*`）携带一个活动中的 agent。能力事件挂接策略和适配器。

到达模型请求的内容必须能从会话日志重建，因此新的模型可见输入需要一条会话事件。在这份快照里，`packages/core/session/src/types.ts` 中的 `SESSION_FORMAT_VERSION` 是 `0`，SQLite 持久化使用 `packages/session/session-persistence-sqlite/src/schema.ts` 中的 `SCHEMA_VERSION` `17`。不认识某条必需会话事件类型的构建会拒绝该日志，除非该事件被标成可忽略。只有结构性的格式变更才提升 `SESSION_FORMAT_VERSION`。

包分组及其职责见 [packages/README.md](../packages/README.zh.md)。下表是二开改动通常会碰到的区域。每个包的 README 拥有它自己的约定。

## 改代码之前要理解的事

改 `packages/` 之前先读 [architecture.md](architecture.zh.md)。第一次安装之前先读 [development.md](development.zh.md)。agent 的常驻指令是 [AGENTS.md](../AGENTS.md)。

### 概念

- 插件是产品行为的单位。函数插件具名导出 `name`、`inject`、`Config` 和 `apply`，并且没有默认导出。服务包默认导出自己的服务类。两种形式混用会让 Loader 丢掉函数插件的命名空间。事件记录是 [postmortem 0001](postmortem/0001-acp-default-export-drops-inject.zh.md)。
- `inject` 写出所需服务。插件会等到这些服务存在，因此启动顺序是一份依赖声明。
- 其他插件通过 context 键找到服务，例如 `ctx.tools`、`ctx.llm` 或 `ctx.sessions`。
- 事件使用声明合并。分发方式是 `emit`、`waterfall`（瀑布式事件）、`parallel` 或 `serial`。waterfall 监听器收到 `next`，并且必须调用 `next()` 才能继续委托。不调用 `next()` 就返回会短路整条链。
- 一个轮次排空已接纳的输入。一个步骤是一次模型请求，加上该请求调用的工具。顺序画在 [architecture.md](architecture.zh.md) 里。
- Host 与 Client 是两个 TypeScript 程序。一个程序不得同时包含两套 `Context` 合并。新包只注册进一个 aggregate。布局规则在 [development.md](development.zh.md)。

### 扩展点

[architecture.md](architecture.zh.md) 里的机制表是「改动该放在哪里」的依据。常见选择是：

- 模型提供方在 `ctx.llm` 上注册适配器。按[添加 LLM 适配器](cookbook/adding-an-llm-adapter.zh.md) 做。
- 面向模型的工具在 `ctx.tools` 上注册。按[添加工具](cookbook/adding-a-tool.zh.md) 做。
- 人类使用的斜杠命令在 `ctx.commands` 上注册，并且不启动模型轮次。
- 文件系统、shell、subprocess、sandbox 和 web 能力各自有服务键。该 seam 已经存在时，增加一个提供方。
- 持久状态扩展 `SessionEventMap`，并从日志渲染。
- 按会话组装使用预设 `cordis.yml`，经过 [`packages/preset`](../packages/preset/README.zh.md)。
- 树外插件用 `dsh plugin` 装进一个 profile，然后出现在该 profile 的 patch 层里。

创建包的步骤在[添加包](cookbook/adding-a-package.zh.md)。工具、hook 和 UI 插件的形态在[扩展手册](cookbook/extension-cookbook.zh.md)。

### 配置、凭据与模型提供方

`cordis.yml` 在插件的 `config` 以及条目的 `disabled` 字段下接受 `!!js`。其他条目元数据保持字面量。`!!js` 表达不了条件时，组装改用 overlay。Loader 规则在[入门](cordis-primer.zh.md)。

配置保存的是凭据引用，不是密钥值。[`dsh-credentials-local`](../packages/credentials/credentials-local/README.zh.md) 解析四层：启动时的环境，然后是 `$DSH_HOME/.credentials.yaml`，然后是 `<cwd>/.env`，然后是 `$DSH_HOME/.env`。启动时的环境优先。产品 CLI（命令行界面）读取一份冻结的环境快照，因此启动之后再导出的变量要到下一次启动才可见。

[`dsh-llm-deepseek`](../packages/llm/llm-deepseek/README.zh.md) 拥有提供方路由 `deepseek-official`。它的 `apiKeyEnv` 默认为 `DEEPSEEK_API_KEY`，并在每次请求时经 `ctx.credentials` 解析。省略 `baseURL` 时，先用 `DEEPSEEK_BASE_URL`，再用公共 API。[`dsh-llm-pi-ai`](../packages/llm/llm-pi-ai/README.zh.md) 是一个插件，其配置是提供方 profile 的字典。每个 profile 的 `apiKeyEnv` 是类似 `OPENAI_API_KEY` 的引用。同一条路由注册两次会抛错。家族地图是 [packages/llm](../packages/llm/README.zh.md)。

### 插件生命周期

Loader 在条目声明的注入都已激活之后挂载该条目。`apply` 或服务构造函数注册 effect。该插件所在的 fiber 卸载，或配置行被移除时，这些 disposer 会执行。卸载之后仍然留下的贡献是缺陷，包测试必须展示这次移除。热重载是 [vendor/README.md](../vendor/README.md) 所描述的、随仓库提供的 HMR（热模块替换）插件。自洽的错误配置在加载时失败。其余错误配置在第一个能够被发现的时刻失败。缺失的引用会被报告，而不是被跳过。

## 准备清单

下面的步骤是搭建过程。它们背后的贡献者参考是 [development.md](development.zh.md)。

### 工具链

- Node.js 必须满足根 `package.json` 里的 `engines.node`：`^22.19.0 || >=24.0.0`。CI 的主版本是 Node 24，来自 `.github/workflows/ci.yml` 的 `PRIMARY_NODE_VERSION`。其余 CI 通道运行 Node 22.19 和 Node 26。
- 包管理器是启用了 Corepack 的 pnpm。根字段 `packageManager` 是 `pnpm@11.7.0`。
- `packageManager`、`engines` 和 CI 工作流都没有写出 Bun。本仓库的安装和任务脚本是 pnpm 脚本。
- Git 必须是 2.26 或更高。`pnpm install` 会运行 `scripts/install-lefthook.mjs`，它安装 worktree 本地的 Lefthook 钩子和翻译配对合并驱动。
- `pnpm install` 需要访问 npm registry 的网络。分析机上默认的 `node` 二进制是 v22.14.0，低于引擎下限。nvm 里的 Node v22.22.2 满足该范围。

### 环境变量

把密钥放在仓库根目录被 git 忽略的 `.env` 里，或在 shell 中导出。不要提交密钥材料。

| 变量 | 在这份快照中的作用 |
|---|---|
| `DEEPSEEK_API_KEY` | 为实时 DeepSeek 调用、headless 与 ACP（Agent Client Protocol）演示，以及真实 API 的 e2e 授权。该变量未设置时，这些 e2e 测试会自行跳过。 |
| `DEEPSEEK_BASE_URL` | 插件省略 `baseURL` 时，DeepSeek 直连适配器使用的可选 API 基址。 |
| `DSH_HOME` | Harness home。未设置时，home 是 `~/.dsh`。profile、`.credentials.yaml` 和 `.anonymous-user-id` 存放在那里。 |
| `DSH_PERMISSION_MODE` | base 组合包的 sandbox 模式。未设置时，模式是 `workspace-write`。`danger-full-access` 还会把审批策略选成 `never`。 |
| `DSH_TELEMETRY_MODE` | 会话日志导出的同意开关。未设置和空值都解析为 `DISABLED`。`FULL` 和 `FEEDBACK_ONLY` 表示同意导出。 |
| `DSH_TELEMETRY_DISABLED` | 任意非空值，包括 `0` 和 `false`，都会在加载前禁用遥测配置行。 |
| `DSH_TELEMETRY_OTLP_URL` | 启用导出时使用的可选 OTLP/HTTP 日志端点。 |

`DSH_TELEMETRY_DISABLED` 会停止遥测导出。已授权的 DeepSeek 请求仍然可以创建匿名用户 id。这个划分记录在[匿名用户 id Agent Note](../.agents/notes/implemented/feature/2026-07-31-telemetry-anonymous-user-id.zh.md)。

### 第一次运行

在仓库根目录：

```sh
corepack enable
pnpm install
pnpm run typecheck
pnpm run build
pnpm dsh web
```

`pnpm run typecheck` 是开发指南里的搭建完成检查。在 `pnpm dsh web`、`pnpm dsh --profile headless "task"`、`pnpm run demo:cordis` 和 `pnpm run demo:acp` 之前先运行 `pnpm run build`。headless、Cordis 和 ACP 演示需要 `DEEPSEEK_API_KEY`。`pnpm run test` 是不需要密钥的 Vitest 运行。`pnpm run test:e2e` 是真实 API 套件，密钥缺失时自行跳过。`pnpm run test:snapshot` 回放不需要密钥的 ACP 和 headless transcript（文本记录）。

### 检查与阅读

选择能覆盖这次编辑的检查。文档编辑运行 `pnpm run doc-sync`。行为编辑运行所属的 Vitest 文件。用户或模型能看到的产品输出，要更新 `examples/` 下的无密钥快照。选择规则在 [AGENTS.md](../AGENTS.md) 和 [testing.md](testing.zh.md)。CI 负责覆盖率、Node 矩阵和已构建产物的冒烟。把 `pnpm run test:coverage` 留给全仓库改动，或留给覆盖率失败的诊断。

`docs/` 下的每篇文档都是英文和中文的一对：`foo.md`、`foo.zh.md` 和 `foo.i18n.yaml`。编辑任意一侧时，要更新另一侧，然后运行 `pnpm run verify-translation-pairing --write <pair>`。约定是 [i18n/README.md](i18n/README.zh.md)。

## 建议的二开路径

本节的计划遵循 2026-09-28 的快照。它是本 fork 的工作计划，不是上游的产品决策。

### 用插件扩展

把应当在上游同步之后仍然保留的行为放进插件。从 profile 的 `cordis.patch.yml` 挂载它，或从用 `dsh plugin` 安装的树外包挂载，或从遵循[添加包](cookbook/adding-a-package.zh.md) 的新工作区包挂载。seam 已经存在时，为它增加 Service Provider，并保留现有 Consumer。模型必须看到新行为时，在同一次改动里加上会话事件。对 `packages/core/agent-loop` 的改动也要在同一次改动里更新 [architecture.md](architecture.zh.md)。

只有扩展点表达不了该行为时，才在树内分叉 core。把这项工作放在一条分支上，并让这条分支独有的提交小到能够变基到 parent `master`。

### 让 master 保持可快进

在 2026-09-28，fork 的 `master` 是 parent `master` 的祖先。这一点保持成立时，下面的序列用快进更新 fork：

```sh
git remote add upstream https://github.com/deepseek-ai/deepseek-harness.git
git fetch upstream
git checkout master
git merge --ff-only upstream/master
git push origin master
```

`upstream` 这个 remote 加一次即可。本 fork 出现 parent `master` 所没有的提交之后，`--ff-only` 会失败，更新变成合并或变基。把 GitHub 上的 `master` 保持为那条快进镜像，把二开提交落到其他分支。跨越这 7030 次提交的快进会让 `package.json` 离开 `0.1.1-rc.2`，并且可能提高 `SCHEMA_VERSION`。本快照写下的会话数据库届时可能打不开。在第一次启动更新后的树之前，先复制 `$DSH_HOME`。

### 分支与 PR

本 fork 包含上游模板 [.github/pull_request_template.md](../.github/pull_request_template.md)。[AGENTS.md](../AGENTS.md) 里的上游评审约定要求一个 `kind/*` 标签、全部相关的 `area/*` 标签，并在改动改变行为、架构、共享约定、流程、测试策略或磁盘格式时写一篇 Agent Note。所阅读的文件树没有增加一套 fork 专用的标签或 issue 跟踪。在 fork 写明替代规则之前，使用该模板。

把只改文档的变更或只改插件的变更放在 `master` 以外的分支上，并把上游同步放进它自己的 PR（Pull Request）。同步混进功能分支之后，快进或变基更难评审。

### 会破坏同步的区域

- `vendor/*/src` 下的编辑必须记入 [vendor/README.md](../vendor/README.md)，并在每次 Cordis 同步时重新应用。
- `SessionEventMap`、`SESSION_FORMAT_VERSION` 和 SQLite 的 `SCHEMA_VERSION` 是兼容边界。这份快照的预发布立场拒绝旧的磁盘格式。
- 生成的目录，包括 `docs/tool-catalog.md`、`docs/config-catalog.md`、`docs/module-graph.md` 和 Cordis API 页面，都从源码重新生成。要改的是生成器的输入。
- 一个同时包含 Host 与 Client 两套 `Context` 合并的 TypeScript 程序会使构建失败。遵循 [development.md](development.zh.md)。

## 陷阱与待确认项

- 根 README 给出的仍然是上游克隆 URL。按那个 URL 操作的队友不会克隆到本 fork。
- 在 `pnpm run build` 之前执行 `pnpm dsh` 会启动源码启动器，而生产运行仍然需要已构建的包产物和前端产物。开发指南写明了这项要求。
- `$DSH_HOME` 下的文件可以被以同一用户运行的工具进程读取。credentials-local 的 README 写明，模式 `0600` 不能对 agent 隐藏 `.credentials.yaml`。
- 默认遥测模式是 `DISABLED`。`DSH_TELEMETRY_MODE=FULL` 或 `FEEDBACK_ONLY` 会导出会话日志材料。非空的 `DSH_TELEMETRY_DISABLED` 即使模式被改过，也让这次运行留在本地。
- 低于 22.19 的 Node 在 `engines.node` 之外。分析环境演示了这一点：它默认的 `node` 是 v22.14.0。
- 领先和落后的计数是 2026-09-28 的观察。做同步计划之前先刷新它们。
- 待确认：Origin 仓库 `eqkk/deepseek-harness` 在本环境中不可读。请确认它是 `eqkkk/deepseek-harness` 的镜像，还是含有其他提交。
- 待确认：第一份产品补丁应当快进到上游 `master`，还是停在 tag `dsh-v0.1.7-rc.2`。从本 HEAD 出发，两者都是快进。`master` 比该 tag 多 155 次提交。
- 待确认：产品目标是哪个 profile（`web`、`headless`、ACP、JSON-RPC，或 Python SDK）。第一个插件应当在该 profile 的 `cordis.yml` 里得到验证，因为扩展点并不相同。
